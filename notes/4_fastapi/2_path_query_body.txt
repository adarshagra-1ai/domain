2  --  Path params, query params, JSON body

1)  Three ways a route takes input

A FastAPI route can receive data from
three places in the request:

     PATH PARAMS   ->  part of the URL
                       itself
                       /users/{user_id}
     QUERY PARAMS  ->  after  ?  in the
                       URL
                       /search?q=python
     BODY (JSON)   ->  the request body,
                       for POST / PUT /
                       PATCH


2)  Path parameters

Put the name in curly braces in the path.
Add a matching function argument.

Code:

     from fastapi import FastAPI

     app = FastAPI()

     @app.get("/users/{user_id}")
     def get_user(user_id: int):
         return {"user_id": user_id}

Run:

     uvicorn main:app --reload

Try:

     curl http://127.0.0.1:8000/users/42

Output:

     {"user_id":42}

Notes:

  -  {user_id}  in the path must match
     the argument name in the function.
  -  The type hint  user_id: int  tells
     FastAPI to CONVERT the value to int.
  -  If the value cannot convert (for
     example  curl .../users/hello ),
     FastAPI returns  422 Unprocessable
     Entity  automatically.


Type conversion in path params:

     user_id: int    ->  integer required
     price:  float   ->  float required
     name:   str     ->  any string
                         (the default)


Multiple path params:

Code:

     @app.get("/users/{user_id}/orders/{order_id}")
     def get_order(user_id: int, order_id: int):
         return {"user": user_id,
                 "order": order_id}

Try:

     curl http://127.0.0.1:8000/users/42/orders/7

Output:

     {"user":42,"order":7}


3)  Query parameters

Any function argument that is NOT part of
the path is treated as a QUERY parameter.

Code:

     @app.get("/search")
     def search(q: str):
         return {"query": q}

Try:

     curl "http://127.0.0.1:8000/search?q=python"

Output:

     {"query":"python"}

The  ?q=python  in the URL is the query
string.


4)  Optional query params (with defaults)

Give the parameter a default value. It
becomes optional in the URL.

Code:

     @app.get("/search")
     def search(q: str, limit: int = 10):
         return {"query": q, "limit": limit}

Try:

     curl "http://127.0.0.1:8000/search?q=python"
     curl "http://127.0.0.1:8000/search?q=python&limit=25"

Outputs:

     {"query":"python","limit":10}
     {"query":"python","limit":25}


5)  Multiple query params

Separate them with  &  in the URL.

Code:

     @app.get("/products")
     def products(category: str = "all",
                  min_price: float = 0.0,
                  max_price: float = 1000.0):
         return {"category": category,
                 "min_price": min_price,
                 "max_price": max_price}

Try:

     curl "http://127.0.0.1:8000/products?category=books&min_price=100"

Output:

     {"category":"books","min_price":100.0,"max_price":1000.0}


6)  JSON body

For POST / PUT / PATCH requests, the data
usually comes in the request body as JSON.

You accept it by declaring a Pydantic
model as a parameter (deep dive in section 3).
For now, the shape is:

Code:

     from fastapi import FastAPI
     from pydantic import BaseModel

     class NewUser(BaseModel):
         name: str
         age: int

     app = FastAPI()

     @app.post("/users")
     def create_user(user: NewUser):
         return {"created": user.name,
                 "age": user.age}

Try:

     curl -X POST \
          -H "Content-Type: application/json" \
          -d '{"name":"adarsh","age":25}' \
          http://127.0.0.1:8000/users

Output:

     {"created":"adarsh","age":25}

Full Pydantic details in section 3.


7)  Path + query + body together

You can mix all three in one route.
FastAPI figures out which parameter
comes from where:

  -  In the path         ->  path param
  -  Has a Pydantic       ->  body
     model type
  -  Anything else       ->  query param

Code:

     @app.put("/users/{user_id}")
     def update_user(user_id: int,
                     notify: bool = True,
                     data: NewUser = None):
         return {"user_id": user_id,
                 "notify": notify,
                 "data": data}


8)  Automatic validation error output

Try:

     curl http://127.0.0.1:8000/users/abc

Response (status 422):

     {"detail":[{"type":"int_parsing",
                 "loc":["path","user_id"],
                 "msg":"Input should be a
                       valid integer, unable
                       to parse string as an
                       integer",
                 "input":"abc"}]}

FastAPI validated the input against the
int  type hint, saw the failure, and
returned  422 Unprocessable Entity
automatically  --  without your handler
even running.


9)  Common errors

  (a)   Name mismatch between path and
        argument

        Code:

           @app.get("/users/{user_id}")
           def get_user(id: int):
               ...

        The path uses  user_id  but the
        function uses  id . FastAPI does
        not know how to fill  id , and
        the route breaks. Make the names
        match.


  (b)   Wrong type in the URL

        curl .../users/abc  with a route
        that expects  user_id: int  gives
        422 Unprocessable Entity  from
        FastAPI's validator.


  (c)   Forgetting -H Content-Type on POST

        Same as HTTP gotcha in the HTTP topic: with
        no  Content-Type:
        application/json , the body is
        not parsed as JSON.


  (d)   Body vs query confusion

        Convention: use QUERY for
        FILTERING and OPTIONS. Use BODY
        for the CONTENT being created or
        updated. Do not send a big JSON
        payload as a query string.


In section 3 we look at PYDANTIC models  --
how the body of a request gets validated
and turned into a typed Python object.

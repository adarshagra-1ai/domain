14  --  Modules and import
          (own module, standard library,
           third-party module)

1)  What a module is

A MODULE is a Python file ( .py ) whose
contents (variables, functions, classes)
can be used from OTHER Python files by
IMPORTING it.

You have already been writing modules
without knowing it. Every  .py  file is a
module.

A LIBRARY (or "package") is usually a
collection of related modules bundled
together.


2)  import  --  the basic form

Syntax:

     import <module_name>

After this line, you can use the names
inside that module with dot syntax:

     <module_name>.<name>

Code:

     import math

     print(math.pi)
     print(math.sqrt(16))

Output:
     3.141592653589793
     4.0

math  is a module in Python's STANDARD
LIBRARY (built-in, no install needed).
pi  is a variable inside it;
sqrt  is a function inside it.


3)  from ... import ...   --  bring specific
    names into scope

Sometimes you only need one or two names
from a module. Import them directly and
use them without the module prefix.

Code:

     from math import pi, sqrt

     print(pi)
     print(sqrt(25))

Output:
     3.141592653589793
     5.0

Now  pi  and  sqrt  are directly
available, no  math.  prefix.


Avoid  from module import *  (star
import). It brings in every name and can
silently overwrite your own variables.
Explicit is better.


4)  import ... as ...   --  give the module a
    shorter name (alias)

Handy for modules with long names.

Code:

     import datetime as dt

     print(dt.date.today())

Output:  (today's date)


Common conventions from the ecosystem:

     import numpy as np
     import pandas as pd
     import matplotlib.pyplot as plt

You can also alias a specific name:

     from math import sqrt as square_root


5)  Your own module

Any  .py  file in your CWD (or on the
Python search path) can be imported.

Suppose you have a file  helpers.py  in
the same folder as your main script:

     helpers.py
     ----------
     def greet(name):
         return f"hello, {name}"

     def square(x):
         return x * x


From another file in the same folder:

     main.py
     -------
     import helpers

     print(helpers.greet("adarsh"))
     print(helpers.square(4))

Run:

     python3 main.py

Output:
     hello, adarsh
     16


You can also use  from helpers import ... :

     from helpers import greet
     print(greet("adarsh"))


Note: the module NAME is the file name
WITHOUT  .py . So  helpers.py  is
imported as  import helpers  (not
import helpers.py ).


6)  Standard library  --  a taste

Python ships with a large STANDARD LIBRARY.
Some commonly used modules:

     math         math functions and
                  constants
     os           operating-system level
                  things: paths, env
                  vars, folder listings
     sys          Python interpreter info,
                  command-line arguments
     json         read and write JSON text
     datetime     dates and times
     random       random numbers,
                  shuffling, random choice
     re           regular expressions
     pathlib      modern object-oriented
                  path handling

Small examples:


Before we use the  json  module, a
quick word on what JSON is.

JSON (JavaScript Object Notation) is a
TEXT format for representing data. The
name comes from JavaScript, but it is
now used by every major language for
exchanging data (between programs, over
the network, in config files, etc.).

Key facts:

  -  It is plain TEXT (a string). Not
     binary.
  -  Human-readable  --  you can open a
     JSON file and understand it.
  -  Structure looks a lot like a Python
     dict, so it maps to Python cleanly.
  -  Web APIs almost always exchange
     data as JSON.


A JSON example:

     {
         "name": "adarsh",
         "age": 25,
         "is_active": true,
         "tags": ["python", "web"],
         "address": {
             "city": "delhi",
             "zip": "110001"
         }
     }


JSON types map to Python types like this:

     JSON string    ->  Python str
     JSON number    ->  Python int or float
     JSON true      ->  Python True
     JSON false     ->  Python False
     JSON null      ->  Python None
     JSON array     ->  Python list
     JSON object    ->  Python dict


Small differences from Python:

  -  Keys in a JSON object MUST be
     DOUBLE-QUOTED strings. In Python
     dicts, keys can be any hashable
     type.
  -  JSON booleans are LOWERCASE
     ( true , false ). Python uses
     True , False .
  -  JSON's "no value" is  null .
     Python uses  None .
  -  JSON forbids trailing commas after
     the last item. Python allows them.
  -  JSON only allows DOUBLE quotes for
     strings. Python allows single or
     double.

The Python  json  module handles all of
these differences for you.


About  json.dumps  and  json.loads :

     dumps    "dump string"  --  convert a
              Python object (dict, list,
              number, string, bool, None)
              INTO a JSON string.

     loads    "load string"  --  parse a
              JSON string INTO a Python
              object.

The names use the  s  suffix for
"string". Without the  s
( json.dump  and  json.load ) the same
functions work with FILE OBJECTS
instead of strings  --  useful when you
want to save or read JSON directly to
or from a file.


Common shape of both functions:

     json.dumps(<python_obj>)
        ->  str  (JSON text)

     json.loads(<json_str>)
        ->  Python object

     json.dump(<python_obj>, <file>)
        ->  writes JSON text to the file

     json.load(<file>)
        ->  reads JSON text from the file
            and parses it

Code:

     import json

     data = {"name": "adarsh", "age": 25}
     text = json.dumps(data)
     print(text)

     back = json.loads(text)
     print(back)

Output:
     {"name": "adarsh", "age": 25}
     {'name': 'adarsh', 'age': 25}


Why the two output lines look different:

     text  (from  dumps ):
        {"name": "adarsh", "age": 25}
        DOUBLE quotes  --  the required
        JSON syntax.

     back  (from  loads ):
        {'name': 'adarsh', 'age': 25}
        SINGLE quotes  --  Python's
        default way of printing a dict.

They represent the SAME data. The first
line is JSON text; the second line is a
Python dict.


Code:

     import random

     print(random.choice(["a", "b", "c"]))
     print(random.randint(1, 6))

Output:  (varies each run)


Code:

     from datetime import date

     today = date.today()
     print(today)
     print(today.year)

Output:  (varies)


You do NOT need to install any of these
--  they come with Python.


7)  Third-party modules

Anything NOT in the standard library is
called a THIRD-PARTY module. You install
it with  pip . Common ones:

     requests    HTTP requests
     fastapi     web framework we will
                 use in the FastAPI topic
     litellm     LLM library we will use
                 in the AI agent topic later

Basic install command (details and best
practice with virtual environments come
in section 18 and section 19):

     pip install <name>

For example:

     pip install requests

After installing, use it like any other
module:

     import requests

     r = requests.get("https://example.com")
     print(r.status_code)


8)  Where does Python look for modules?

When you write  import x , Python
searches in this order:

     1.  Built-in modules.
     2.  The folder of the running script
         (your CWD in simple cases).
     3.  Directories listed in the
         environment variable
         PYTHONPATH .
     4.  The installation-specific
         "site-packages" folder (where
         pip installs third-party
         modules).

You can inspect the full list at runtime:

Code:

     import sys
     for p in sys.path:
         print(p)

Output:  (list of directories)


9)  __name__ == "__main__"

At the bottom of many Python files you
will see:

     if __name__ == "__main__":
         <code to run when the file is
          executed directly>

This block runs ONLY when you execute the
file directly with  python3 file.py . If
another file  import s it, the block does
NOT run.

Useful when a module both EXPORTS
functions AND can run as a script.


10)  Common errors

  (a)   Module not found

        Run:

           python3 main.py
           ModuleNotFoundError: No module
           named 'helpers'

        Reasons:

        -  You mistyped the module name.
        -  The file  helpers.py  is not
           in your CWD.
        -  You are trying to import a
           third-party module you have
           not installed yet
           ( pip install <name>  first).


  (b)   Circular import

        Two files each import each other.
        You get partly-loaded modules and
        confusing  ImportError  s.
        Restructure so one file does not
        depend on the other, or move the
        shared code into a third file.


  (c)   Shadowing a standard-library name

        If you save a file called
        math.py  in the same folder as
        your script, then  import math
        will import YOUR file, not the
        real  math  library. Avoid
        standard-library names for your
        own module files.

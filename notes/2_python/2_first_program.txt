2  --  First Python program

1)  What each piece of  print("hello")  means

     print      ->  the NAME of a built-in Python function that prints text to the screen.

     ( ... )    ->  parentheses  --  they say "CALL this function with the values inside".

     "hello"    ->  a STRING (a piece of text). Strings in Python are wrapped in double quotes  "..."  or single quotes  '...' . Both work.

The whole line reads as:  "call the  print  function with the string  hello ".

2)  Create the file

Two easy ways to create  hello.py .

Way A  --  from the terminal (no editor needed):

     adarsh@laptop:~$  echo 'print("hello")' > hello.py

Two new pieces here:

  -  echo  is a shell command that prints the text you give it. On its own,

        adarsh@laptop:~$  echo hello
        hello

     just prints  hello  to the screen.

  -  The  >  symbol REDIRECTS the output of the command on its left into the file on the right, instead of printing it to the screen. If the file does not exist, it is created. If it exists, its contents are OVERWRITTEN with the new output.

So the full line  echo 'print("hello")' > hello.py  takes the text  print("hello")  and writes it into a new file called  hello.py .

Both  echo  and  >  are covered properly in the terminal topic, section 4. For now use this one-liner as a quick "write one line to a file" trick.

Verify what got written:

     adarsh@laptop:~$  cat hello.py
     print("hello")

Way B  --  in a text editor:

Open any text editor (VS Code (Visual Studio Code), gedit, your IDE (Integrated Development Environment), etc.), create a new file named  hello.py  in your current folder, put this one line inside:

     print("hello")

Save the file.

3)  Run the file

Make sure your CWD (Current Working Directory) is the folder that contains  hello.py  (use  pwd  to check,  cd  if needed).

     adarsh@laptop:~$  python3 hello.py
     hello

python3  is the INTERPRETER. Its job is to read  .py  files and run them.

4)  Try small variations

Same file, different content, same run command. Edit  hello.py , save, re-run.

Change the text:

     print("hello, world")

Run:

     adarsh@laptop:~$  python3 hello.py
     hello, world

Print a number:

     print(2025)

Run:

     adarsh@laptop:~$  python3 hello.py
     2025

Numbers do NOT need quotes.  2025  is a number, not a string.

Two lines of output:

     print("line 1")
     print("line 2")

Run:

     adarsh@laptop:~$  python3 hello.py
     line 1
     line 2

Each  print  call ends with a newline, so the next  print  starts on a fresh line.

5)  Common errors

  (a)   File not found

        adarsh@laptop:~$  python3 hello.py
        python3: can't open file '/home/adarsh/hello.py': [Errno 2] No such file or directory

        Wrong CWD, or the file is not exactly  hello.py . Fix with  pwd  and  ls .

  (b)   Missing quotes

        Content:  print(hello)

        Run:

        adarsh@laptop:~$  python3 hello.py
        Traceback (most recent call last):
          File "hello.py", line 1, in <module>
            print(hello)
        NameError: name 'hello' is not defined

        Without quotes, Python thinks  hello  is a variable name (not text). Since no such variable was defined, it errors. Add the quotes:  print("hello") .

  (c)   Mismatched quotes

        Content:  print("hello')

        Run:

        adarsh@laptop:~$  python3 hello.py
          File "hello.py", line 1
            print("hello')
                       ^^^^^^^^^
        SyntaxError: unterminated string literal

        Opening quote and closing quote must MATCH: both double  " ... "  or both single  ' ... '  .

  (d)   python3 not found

        adarsh@laptop:~$  python3 hello.py
        bash: python3: command not found

        Python is not installed. Go back to section 1 sub-section 4.

6)  Comments  --  notes for humans that Python ignores

A COMMENT is text inside a  .py  file that Python does not run. It is there for the person reading the code.

The  #  character starts a comment. Everything from  #  to the end of that line is ignored.

Whole-line comment:

     # this line does nothing
     print("hello")

Run:

     adarsh@laptop:~$  python3 hello.py
     hello

Only  hello  printed. The first line was skipped completely.

Inline comment  --  a  #  after real code on the same line:

     print("hello")     # this part is ignored

Run:

     adarsh@laptop:~$  python3 hello.py
     hello

The code before the  #  still runs; only the tail is ignored.

Facts:

  -  A comment can hold anything  --  words, punctuation, even code. Python never looks at it.
  -  There is no "start" and "end" comment marker in Python. Each comment line needs its own  # .
  -  A  #  INSIDE a string is not a comment. It is just a character in the text.

Code:

     print("price is #5")

Output:

     price is #5

The  #  sat inside the quotes, so it is part of the string, not the start of a comment.

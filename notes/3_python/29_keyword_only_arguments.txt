29  --  keyword-only arguments: the bare  *  separator in function signatures

1)  What a keyword-only argument is

A keyword-only argument is a function parameter that the caller MUST pass by name, not by position. You mark it by placing a bare  *  (star) in the parameter list; everything AFTER the star becomes keyword-only.

     def connect(host, port, *, use_ssl=False, timeout=30):
         ...

Calling it:

     connect("localhost", 8080, use_ssl=True)     OK
     connect("localhost", 8080, True)             TypeError

In the second call, Python refuses to accept  True  as a positional argument for  use_ssl , because the bare  *  in the definition said "everything past this point must be given by keyword name".

2)  The bare star syntax

     def f(a, b, *, c, d):
         ...

  -  Everything BEFORE the  *   ->  can be passed positionally OR by keyword.
  -  The  *  itself is just a marker. It is not a real parameter; it does not receive a value.
  -  Everything AFTER the  *   ->  MUST be passed by keyword name.

Keyword-only parameters can have default values or not. If they have no default, the caller MUST supply them by name  --  omitting them is a  TypeError .

     def f(a, b, *, c, d=10):
         ...

Calling it:

     f(1, 2, c=3)        OK, d defaults to 10
     f(1, 2, c=3, d=4)   OK
     f(1, 2)             TypeError: missing required keyword-only argument: 'c'
     f(1, 2, 3, 4)       TypeError: too many positional arguments

3)  Why we do it

Three practical reasons:

  (a)  READABILITY AT THE CALL SITE

       Compare these two calls:

           create_user("Adarsh", 25, True, False, True)
           create_user("Adarsh", 25, is_admin=True, send_email=False, active=True)

       The second one tells you at a glance what each argument means. When a function has several boolean or flag-like parameters, forcing them to be keyword-only makes every call self-documenting.

  (b)  PREVENT WRONG-ORDER BUGS

       If a function has parameters  (retry_count, timeout, verbose)  and callers pass them positionally, a small reorder in the definition later can silently swap values  --  no error, just wrong behaviour. Keyword-only forces the caller to name each one, so reorders in the definition do not break existing calls.

  (c)  SAFER API EVOLUTION

       You can add new keyword-only parameters later WITHOUT breaking old code, because old callers never used positions for them anyway. Positional parameters are much harder to rearrange or add to without breaking existing callers.

4)  A concrete example

Without keyword-only:

     def send_message(user, text, urgent=False, silent=False):
         print(user, text, urgent, silent)

     send_message("Adarsh", "hi", True, False)

Reading that call, there is no way to tell what  True  and  False  mean without opening the function definition.

With keyword-only:

     def send_message(user, text, *, urgent=False, silent=False):
         print(user, text, urgent, silent)

Calling it:

     send_message("Adarsh", "hi", urgent=True)   clear at a glance
     send_message("Adarsh", "hi", True)          TypeError, which forces the clear form

The keyword-only version rules out the confusing call shape entirely.

5)  Relation to  *args

Do not confuse a BARE  *  with  *args :

  -   *args  collects extra positional arguments into a tuple. It IS a parameter and receives values.
  -  A bare  *  by itself receives NOTHING. It is only a separator marking the boundary between positional and keyword-only parameters.

If you already have  *args  in the definition, everything AFTER  *args  is automatically keyword-only, and you do not need a bare  *  as well:

     def f(a, *args, b, c=10):
         ...

Here  b  and  c  are keyword-only. Calling  f(1, 2, 3, b=99)  gives  a=1 ,  args=(2, 3) ,  b=99 ,  c=10 .

6)  Common mistakes

  -  Trying to pass a keyword-only argument by position. Gives  TypeError: too many positional arguments . Fix: use the name.

  -  Forgetting the bare  *  when you meant to add it. Without it, everything is positional-or-keyword and the safety is lost.

  -  Writing  def f(*, a, b):  and then calling  f(1, 2) . Fails. The correct call is  f(a=1, b=2) .

  -  Confusing a bare  *  with  *args . They look similar but do different things:  *  is only a separator,  *args  is a real parameter that collects a tuple.

  -  Putting the  *  in the wrong place. Everything AFTER it becomes keyword-only, everything BEFORE stays flexible  --  get the split right for your API (Application Programming Interface).

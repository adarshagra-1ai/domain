2  --  First Python program

1)  What each piece of  print("hello")  means

     print      ->  the NAME of a built-in Python function that prints text to the screen.

     ( ... )    ->  parentheses  --  they say "CALL this function with the values inside".

     "hello"    ->  a STRING (a piece of text). Strings in Python are wrapped in double quotes  "..."  or single quotes  '...' . Both work.

The whole line reads as:  "call the  print  function with the string  hello ".

2)  Create the file

Two easy ways to create  hello.py .

Way A  --  from the terminal (no editor needed):

     adarsh@laptop:~$  echo 'print("hello")' > hello.py

That line takes the text  print("hello")  and writes it into a new file called  hello.py . Keep it as a quick way to put one line into a file without opening anything.

Note the SINGLE quotes around the whole thing. The text itself contains double quotes, so wrapping it in single quotes keeps the two kinds from colliding.

Verify what got written:

     adarsh@laptop:~$  cat hello.py
     print("hello")

Way B  --  in a text editor:

Open any text editor (VS Code (Visual Studio Code), gedit, your IDE (Integrated Development Environment), etc.), create a new file named  hello.py  in your current folder, put this one line inside:

     print("hello")

Save the file.

3)  Run the file

Make sure your CWD (Current Working Directory) is the folder that contains  hello.py  (use  pwd  to check,  cd  if needed).

     adarsh@laptop:~$  python3 hello.py
     hello

python3  is the INTERPRETER. Its job is to read  .py  files and run them.

The errors you will meet:

  -  Python cannot find the file. Either your CWD is not the folder holding it, or the name is not exactly  hello.py . Check both with  pwd  and  ls .

        adarsh@laptop:~$  python3 hello.py
        python3: can't open file '/home/adarsh/hello.py': [Errno 2] No such file or directory

  -  The text has no quotes around it. Without them Python reads  hello  as the NAME of a variable rather than as text, and no such variable exists.

        Content:  print(hello)

        adarsh@laptop:~$  python3 hello.py
        Traceback (most recent call last):
          File "hello.py", line 1, in <module>
            print(hello)
        NameError: name 'hello' is not defined

  -  The opening and closing quotes do not match. Both must be double  " ... "  or both single  ' ... ' .

        Content:  print("hello')

        adarsh@laptop:~$  python3 hello.py
          File "hello.py", line 1
            print("hello')
                       ^^^^^^^^^
        SyntaxError: unterminated string literal

  -  Python itself is not installed, so the command never even reaches your file.

        adarsh@laptop:~$  python3 hello.py
        bash: python3: command not found

4)  Try small variations

Same file, different content, same run command. Edit  hello.py , save, re-run.

Change the text:

     print("hello, world")

Run:

     adarsh@laptop:~$  python3 hello.py
     hello, world

Print a number:

     print(2025)

Run:

     adarsh@laptop:~$  python3 hello.py
     2025

Numbers do NOT need quotes.  2025  is a number, not a string.

Two lines of output:

     print("line 1")
     print("line 2")

Run:

     adarsh@laptop:~$  python3 hello.py
     line 1
     line 2

Each  print  call ends with a newline, so the next  print  starts on a fresh line.

5)  Comments  --  notes for humans that Python ignores

A COMMENT is text inside a  .py  file that Python does not run. It is there for the person reading the code.

The  #  character starts a comment. Everything from  #  to the end of that line is ignored.

Whole-line comment:

     # this line does nothing
     print("hello")

Run:

     adarsh@laptop:~$  python3 hello.py
     hello

Only  hello  printed. The first line was skipped completely.

Inline comment  --  a  #  after real code on the same line:

     print("hello")     # this part is ignored

Run:

     adarsh@laptop:~$  python3 hello.py
     hello

The code before the  #  still runs; only the tail is ignored.

Facts:

  -  A comment can hold anything  --  words, punctuation, even code. Python never looks at it.
  -  There is no "start" and "end" comment marker in Python. Each comment line needs its own  # .
  -  A  #  INSIDE a string is not a comment. It is just a character in the text.

Code:

     print("price is #5")

Output:

     price is #5

The  #  sat inside the quotes, so it is part of the string, not the start of a comment.

6)  input()  --  read a line typed by the user

print()  sends text OUT to the screen.  input()  is its opposite: it reads a line typed IN on the keyboard.

     input()               waits for a line, returns it
     input("prompt: ")     prints the prompt first, then waits

The program STOPS at the  input()  line and waits until you press Enter.

Code:

     name = input("What is your name? ")
     print("Hello, " + name)

Run  (the  adarsh  below is typed by you, then Enter):

     adarsh@laptop:~$  python3 hello.py
     What is your name? adarsh
     Hello, adarsh

input() ALWAYS returns a string

Even when you type digits, what comes back is text, not a number.

Code:

     age = input("Your age: ")
     print(type(age))

Run:

     adarsh@laptop:~$  python3 hello.py
     Your age: 25
     <class 'str'>

You typed  25 , but  age  holds the STRING  "25" . Doing maths on it directly fails:

Code:

     age = input("Your age: ")
     print(age + 1)

Run:

     TypeError: can only concatenate str (not "int") to str

Wrap it in  int()  to get a number:

Code:

     age = int(input("Your age: "))
     print(age + 1)

Run:

     adarsh@laptop:~$  python3 hello.py
     Your age: 25
     26

int()  turns a string of digits into a real number, so the addition works on numbers instead of text.

7)  print() with  end=  and  sep=

print()  takes two optional parameters that control how the output is laid out.

     end     what to add at the very END of the output. Default is  "\n"  (a newline), which is why every  print  starts on a fresh line.
     sep     the separator placed BETWEEN multiple arguments in one  print  call. Default is  " "  (a single space).

end  --  controlling the line break

What each one adds after the text:

     print("hello")              adds  \n
     print("hello", end="")      adds nothing
     print("hello", end=" ")     adds a space
     print("hello", end="---")   adds  ---

With  end="" , the NEXT print continues on the same line instead of starting a fresh one.

Code:

     print("a", end="")
     print("b", end="")
     print("c")

Output:  abc

sep  --  the gap between arguments

One  print  call can take several arguments separated by commas. Python joins them with  sep .

Code:

     print("a", "b", "c")
     print("a", "b", "c", sep="-")
     print("a", "b", "c", sep="")

Output:
     a b c
     a-b-c
     abc

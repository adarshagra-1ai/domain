3  --  Core commands

We will break this section into 4 small chunks:
   Chunk A  -  Where am I? What's here?  (pwd, ls)
   Chunk B  -  Move around                (cd)
   Chunk C  -  Create and view            (mkdir, touch, cat)
   Chunk D  -  Copy, move, delete         (cp, mv, rm)


3  --  Chunk A  :  Where am I? What's here?  (pwd, ls)

1)  Anatomy of a command line

Every line you type in a shell follows the same
pattern:

     command   options   arguments

Example:

     ls -l /home/adarsh

Broken down:

     ls              ->  COMMAND name
     -l              ->  OPTION (also called
                         "flag" or "switch")
     /home/adarsh    ->  ARGUMENT

  -  COMMAND
     First word on the line. The shell looks it
     up as a program on disk and runs it.

  -  OPTIONS  (also called FLAGS)
     Tweak how the command behaves.
        Short:  one dash, one letter
                   -l    -a    -h    -v
        Long:   two dashes, a full word
                   --help    --version    --recursive
     Many commands accept both forms
     ( ls -a  =  ls --all ).
     Options are optional; leaving them out
     uses the default behavior.

  -  ARGUMENTS
     The thing the command should work on.
     For  ls  it is a folder to list. For  cp
     it is the files to copy. Some commands
     take many arguments, some take zero.

Pieces are separated by at least one SPACE.


Combining short options

Short options can be combined into one dash
group. These two lines are the same:

     ls -a -l -h
     ls -alh

Combining works only for short (single-letter)
options. Long options each need their own
--  prefix.


2)  pwd  --  print working directory

The command  pwd  prints the ABSOLUTE PATH of
your current working directory (CWD)  --  the
folder your terminal is currently sitting in.

Syntax:

     pwd

No arguments. No options for daily use.

Example:

     adarsh@laptop:~$  pwd
     /home/adarsh

     adarsh@laptop:~/Documents$  pwd
     /home/adarsh/Documents

Why it is useful:

  -  Reality check when you feel lost about
     where you are.
  -  Some commands (with relative paths)
     behave based on the CWD, so  pwd  tells
     you the exact starting point.


3)  ls  --  list  (see what is inside a folder)

The command  ls  prints the NAMES of the files
and folders inside a folder.

Syntax:

     ls
     ls  <path-to-folder>

  -  No argument  ->  list the CURRENT folder.
  -  With a path  ->  list THAT folder,
                     without changing your CWD.


Example  --  current folder:

     adarsh@laptop:~$  ls
     Documents  Downloads  Music  Pictures

Names shown side-by-side, separated by spaces.


Example  --  absolute path:

     adarsh@laptop:~$  ls /etc
     hostname  hosts  passwd  ...

Your CWD is still  ~  ; you just peeked into
/etc  without moving.


Example  --  relative path:

     adarsh@laptop:~$  ls Documents
     grocery.txt  notes.txt  School

Documents  is a relative path. Real target:
~ + Documents  =  /home/adarsh/Documents .


4)  Hidden files  (dot-files)

By DEFAULT,  ls  hides any file or folder whose
name starts with a dot ( . ).

Examples of hidden names:

     .bashrc
     .gitconfig
     .ssh
     .vscode

These are usually settings used by programs.
Hiding them keeps  ls  output clean.


To see hidden files, add  -a  ("all"):

     adarsh@laptop:~$  ls -a
     .   ..   .bashrc   .ssh   Documents   ...

Note the two special entries at the top:

     .    the folder itself
     ..   the parent folder

Both were introduced in section 1. They
appear as hidden entries in every folder.

Rule of thumb:

     Plain  ls    ->  everyday view
     ls -a        ->  full view (with dot-files)


5)  Useful ls options

  -l   "LONG" format. Each entry on its own
       line with extra details (permissions,
       owner, size, modification time).

  -h   "HUMAN-readable" sizes. Prints  1.2K ,
       3.4M ,  5.6G  instead of raw bytes.
       Only meaningful together with  -l .


Combining:

     ls -a       ->  names + hidden
     ls -l       ->  long, no hidden
     ls -la      ->  long + hidden
     ls -lah     ->  long + hidden + human sizes

ls -lah  is one of the most common lines
typed on Linux.


6)  Reading the output of  ls -l

     adarsh@laptop:~$  ls -lah
     total 24K
     drwxr-xr-x  4 adarsh adarsh 4.0K Aug 26 11:00 .
     drwxr-xr-x  5 root   root   4.0K Jul 20 22:00 ..
     -rw-r--r--  1 adarsh adarsh  120 Aug 25 09:30 notes.txt
     drwxr-xr-x  2 adarsh adarsh 4.0K Aug 20 14:00 Documents

Ignore the top "total 24K" line for now (total
disk-block count of the folder).

Each other line has 7 columns:

     Column 1  :  Type + Permissions
                  First character  =  type:
                     -   regular file
                     d   directory (folder)
                     l   symbolic link (a
                         shortcut to another
                         file)
                  Next 9 characters describe
                  who can Read, Write, Execute.
                  Permissions in detail later.

     Column 2  :  Link count (hard links to
                  this item; usually 1 for a
                  file).

     Column 3  :  Owner (the user, usually you).

     Column 4  :  Group (the owning group).

     Column 5  :  Size (bytes by default;
                  K / M / G with  -h ).

     Column 6  :  Modification time.

     Column 7  :  Name.

For everyday use you read: Type/Permissions,
Size, Modification time, Name.


3  --  Chunk B  :  Move around  (cd)

1)  What  cd  does

The command  cd  ("Change Directory") moves
your CWD to a folder you name.

After a successful  cd :

  -  Your CWD is the new folder.
  -  Your prompt updates to show the new
     folder.
  -  Every relative path is now read from
     this new folder.

If  cd  fails (target does not exist), your
CWD does not change; the terminal prints an
error and leaves you where you were.


2)  Syntax

     cd  <path-to-folder>
     cd                     (no argument)

Path can be:

  -  Absolute (starts with  / )
  -  Relative (does not start with  / )
  -  Shortcut ( ~ , .. , or - )
  -  Nothing (just  cd )


3)  Moving with an absolute path

     adarsh@laptop:~$  pwd
     /home/adarsh

     adarsh@laptop:~$  cd /etc

     adarsh@laptop:/etc$  pwd
     /etc

The prompt changed from  ~  to  /etc ;  pwd
confirms.

Absolute paths always work regardless of your
starting CWD.


4)  Moving with a relative path

     adarsh@laptop:~$  cd Documents

     adarsh@laptop:~/Documents$  pwd
     /home/adarsh/Documents

You typed just  Documents ; the shell added
your CWD in front.

Chain relative names in one step:

     adarsh@laptop:~$  cd Documents/School

     adarsh@laptop:~/Documents/School$


5)  Special shortcut targets

  (a)   cd ~     go to your HOME folder

        adarsh@laptop:/etc$  cd ~
        adarsh@laptop:~$


  (b)   cd       (no argument)  also go HOME

        adarsh@laptop:/etc$  cd
        adarsh@laptop:~$

        Plain  cd  is the same as  cd ~ .


  (c)   cd ..    go UP one level

        adarsh@laptop:~/Documents/School$  cd ..
        adarsh@laptop:~/Documents$

        Chain them:

        adarsh@laptop:~/Documents/School$  cd ../..
        adarsh@laptop:~$


  (d)   cd -     go back to the PREVIOUS folder

        Flips between the last two folders.

        adarsh@laptop:~$  cd /etc
        adarsh@laptop:/etc$

        adarsh@laptop:/etc$  cd -
        /home/adarsh
        adarsh@laptop:~$

        adarsh@laptop:~$  cd -
        /etc
        adarsh@laptop:/etc$

        cd -  also PRINTS the folder it
        jumped to  --  a handy confirmation.


6)  Mixing shortcuts and folder names

Examples (starting from  ~/Documents/School ):

     cd ../..
        goes up two levels to  /home/adarsh .

     cd ../Downloads
        goes up one level to  ~/Documents  ,
        then into  Downloads .

     cd ~/Downloads
        jumps to  /home/adarsh/Downloads .

     cd /etc/network
        absolute jump to  /etc/network .

     cd ../grocery.txt
        FAILS  --  grocery.txt  is a file,
        not a folder.

Read paths piece by piece, left to right.


7)  Verify with  pwd  after every move

Habit worth building:

  1)  Run  cd <somewhere>
  2)  Immediately run  pwd
  3)  Confirm the CWD is what you expected.

The prompt shows CWD in most setups but can
cut a long path.  pwd  always shows the full
absolute path.


8)  Common problems

  (a)   "No such file or directory"

        adarsh@laptop:~$  cd Docments
        bash: cd: Docments: No such file or directory

        Name does not exist in the current
        folder. Usually a TYPO. Check with
        ls  first.


  (b)   "Not a directory"

        adarsh@laptop:~$  cd notes.txt
        bash: cd: notes.txt: Not a directory

        The name exists but is a FILE.  cd
        moves into folders only.


  (c)   Case sensitivity

        adarsh@laptop:~$  cd documents
        bash: cd: documents: No such file or directory

        Linux paths are case-sensitive.
        Documents  and  documents  are
        different names.


  (d)   Spaces in folder names

        Wrap the path in quotes:

        adarsh@laptop:~$  cd "My Notes"

        Without quotes, the space is a
        separator; the shell thinks you
        gave two arguments.


  (e)   Silent success

        A successful  cd  prints nothing.
        No news is good news.


3  --  Chunk C  :  Create and view  (mkdir, touch, cat)

1)  mkdir  --  make directory

Creates a NEW empty folder at the path you
give.

Syntax:

     mkdir  <path-of-new-folder>

Example:

     adarsh@laptop:~$  mkdir Projects
     adarsh@laptop:~$  ls
     Documents  Downloads  Music  Projects

Path can be relative ( mkdir Projects ) or
absolute ( mkdir /tmp/scratch ).


Many folders in one line:

     adarsh@laptop:~$  mkdir a b c
     adarsh@laptop:~$  ls
     a  b  c


Common problems:

  (a)   Name already exists

        adarsh@laptop:~$  mkdir Documents
        mkdir: cannot create directory 'Documents': File exists


  (b)   Parent folder missing

        adarsh@laptop:~$  mkdir Projects/webapp/src
        mkdir: cannot create directory 'Projects/webapp/src': No such file or directory

        Projects/webapp  does not exist yet.
        Fix:  -p  (next section).


2)  mkdir -p  --  make nested folders in one shot

The  -p  flag ("Parents") creates the WHOLE
CHAIN of missing folders.

     adarsh@laptop:~$  mkdir -p Projects/webapp/src

Silently creates, in order:

     Projects/
     Projects/webapp/
     Projects/webapp/src/

If any already exist,  -p  skips them without
complaining.  mkdir -p  is safe to run many
times.

Rule of thumb:

     One folder that must be new    ->  mkdir
     A chain of folders quietly     ->  mkdir -p


3)  touch  --  create empty file / update timestamp

Two behaviors:

Job A  --  file does NOT exist:

     adarsh@laptop:~$  touch hello.txt
     adarsh@laptop:~$  ls
     hello.txt

New empty file (0 bytes) is created.

Job B  --  file EXISTS:

     adarsh@laptop:~$  ls -lah hello.txt
     -rw-r--r--  1 adarsh adarsh 0 Aug 20 09:00 hello.txt

     adarsh@laptop:~$  touch hello.txt

     adarsh@laptop:~$  ls -lah hello.txt
     -rw-r--r--  1 adarsh adarsh 0 Aug 26 14:35 hello.txt

Timestamp bumped to now. Size and name
unchanged.

  File does NOT exist  ->  create empty file
  File exists          ->  update its timestamp

The tool picks based on whether the file
already exists.


Multiple files at once:

     adarsh@laptop:~$  touch a.txt b.txt c.txt
     adarsh@laptop:~$  ls
     a.txt  b.txt  c.txt


Parent folder missing:

     adarsh@laptop:~$  touch Projects/webapp/README.md
     touch: cannot touch 'Projects/webapp/README.md': No such file or directory

touch  does NOT create missing parent folders.
Use  mkdir -p  first, then  touch .


4)  cat  --  print a file to screen

Reads a file and prints its contents to your
terminal window.

Syntax:

     cat  <file>

Example:

     adarsh@laptop:~$  cat notes.txt
     Meeting is at 5 pm.
     Bring your laptop and the printed report.

Prompt returns on the next line.


Use  cat  for SHORT files (config, one-line
log, few-line note). For big files (thousands
of lines) it dumps everything at once and
scrolls past the top. Better tools ( less ,
head , tail ) come later.


5)  cat with multiple files

The name "concatenate" means "join end to
end".  cat  prints multiple files one after
another with no gap:

     adarsh@laptop:~$  cat part1.txt part2.txt
     first line from part1
     second line from part1
     first line from part2
     second line from part2

All of  part1.txt  , then all of  part2.txt
as one continuous stream. Very useful once we
learn the  >  redirection symbol (later).


6)  Common errors with cat

  (a)   File does not exist

        adarsh@laptop:~$  cat notes.tx
        cat: notes.tx: No such file or directory


  (b)   Target is a folder

        adarsh@laptop:~$  cat Documents
        cat: Documents: Is a directory

        cat  reads FILES.  Use  ls Documents
        to peek inside a folder.


  (c)   Binary file dumps garbage

        adarsh@laptop:~$  cat photo.jpg
        (random-looking characters, terminal
         may beep)

        Binary files (images, videos, PDFs)
        are not text. Dumping them prints raw
        bytes and can leave the terminal
        broken. Use  cat  only on plain-text
        files.


3  --  Chunk D  :  Copy, move, delete  (cp, mv, rm)

Before starting:  rm  can DELETE your files
permanently. There is NO recycle bin. Read the
rm  sections carefully.


1)  cp  --  copy a file

Makes a COPY of a file at a new location. The
original stays where it was.

Syntax:

     cp  <source>  <destination>


Copy in the same folder, new name:

     adarsh@laptop:~$  cp notes.txt notes-backup.txt
     adarsh@laptop:~$  ls
     notes.txt  notes-backup.txt


Copy into a different folder:

     adarsh@laptop:~$  cp notes.txt Documents/

Destination is a folder ->  copy goes INSIDE
with the same file name:
Documents/notes.txt . Trailing slash is
optional.


Copy AND rename in one step:

     adarsh@laptop:~$  cp notes.txt Documents/oldnotes.txt


Copy many files into a folder:

     adarsh@laptop:~$  cp a.txt b.txt c.txt Documents/


2)  cp -r  --  copy a whole folder

By default  cp  refuses folders:

     adarsh@laptop:~$  cp Projects Projects-backup
     cp: -r not specified; omitting directory 'Projects'

The  -r  flag ("Recursive") copies inside
every level.

     adarsh@laptop:~$  cp -r Projects Projects-backup
     adarsh@laptop:~$  ls
     Projects  Projects-backup


3)  Common problems with cp

  (a)   Source does not exist

        adarsh@laptop:~$  cp missing.txt Documents/
        cp: cannot stat 'missing.txt': No such file or directory


  (b)   Destination overwrites silently

        adarsh@laptop:~$  cp a.txt b.txt

        If  b.txt  exists, it is overwritten
        with no warning. To be asked first:

        adarsh@laptop:~$  cp -i a.txt b.txt
        cp: overwrite 'b.txt'?  y

        -i  = "interactive". Good habit while
        learning.


4)  mv  --  move a file  (also RENAME a file)

Moves a file or folder. Original disappears
from the old location.

Syntax:

     mv  <source>  <destination>


Move into a folder:

     adarsh@laptop:~$  ls
     notes.txt  Documents

     adarsh@laptop:~$  mv notes.txt Documents/

     adarsh@laptop:~$  ls
     Documents

     adarsh@laptop:~$  ls Documents
     notes.txt


mv is also RENAME:

     adarsh@laptop:~$  mv notes.txt journal.txt
     adarsh@laptop:~$  ls
     journal.txt

Content unchanged; name is new. Linux does not
have a separate "rename" command;  mv  IS it.


Move a folder (no  -r  needed):

     adarsh@laptop:~$  mv Projects OldProjects

Or:

     adarsh@laptop:~$  mv Projects Documents/

Moving updates a pointer in the file system;
it does not walk through every file to copy
bytes.  -r  not needed.


Common mv problems

  (a)   Silent overwrite (same as cp)

        adarsh@laptop:~$  mv -i a.txt b.txt
        mv: overwrite 'b.txt'?  y


  (b)   Wrong case = accidental rename

        adarsh@laptop:~$  mv notes.txt Notes.txt

        Linux is case-sensitive; this renames
        the file.


5)  rm  --  remove  (DELETE a file)

     WARNING:  rm  deletes files PERMANENTLY.
               No recycle bin, no trash
               folder, no built-in undo. Once
               removed, the file is GONE.


Deletes the file (or files) you name.

Syntax:

     rm  <file>

Example:

     adarsh@laptop:~$  ls
     a.txt  b.txt

     adarsh@laptop:~$  rm a.txt

     adarsh@laptop:~$  ls
     b.txt

Silent success. The file is simply gone.


rm refuses folders by default:

     adarsh@laptop:~$  rm Projects
     rm: cannot remove 'Projects': Is a directory


6)  rm -r  --  remove a folder and everything inside

The  -r  flag ("Recursive") walks the folder,
deletes every file and sub-folder, then
deletes the folder itself.

     adarsh@laptop:~$  rm -r Projects

Everything inside  Projects  is gone
permanently. This is the single most dangerous
command a beginner will run.


7)  Two more flags: -i and -f

  -i   ("interactive")
       Ask before deleting each item.

       adarsh@laptop:~$  rm -i a.txt
       rm: remove regular file 'a.txt'?  y


  -f   ("force")
       Do not ask. Do not complain about
       missing files. Just delete. The
       opposite of  -i .


You will often see  rm -rf <path>  :

     r  ->  recursive
     f  ->  force

Powerful and used by experienced users, but
removes every safety net. Avoid  rm -rf
until you are very sure of the target path.


8)  rm safety habits

  (a)   Always  ls  the path first.

  (b)   Prefer ABSOLUTE paths for  rm  so
        you cannot be confused about the CWD.

  (c)   Use  rm -i  while learning.

  (d)   NEVER run  rm -rf /  or  rm -rf /* .
        Those try to delete the entire file
        system starting from root. Modern
        systems refuse by default, but never
        type them.

  (e)   Keep a backup of anything important
        (cp elsewhere, external drive, or a
        git repo  --  git comes later).


9)  A one-line habit before every rm

Before pressing Enter on  rm , pause and ask:

     "Am I OK if this disappears forever?"

If the answer is anything less than a
confident "yes", stop. Type the command as a
plain  ls  first and see what it lists  --
that same set will be deleted by  rm .

Example  --  before this:

     adarsh@laptop:~$  rm -r Projects/webapp

first run:

     adarsh@laptop:~$  ls -la Projects/webapp

If the listing shows what you meant to
remove, run the  rm . If not, stop and check.

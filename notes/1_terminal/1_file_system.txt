1  --  File System

1)  What is a FILE?

A "file" is a named container that holds data (text, an image, code, anything).

Every file name has two visible parts:

     name  .  extension

Common examples:

     notes.txt      ->  plain text
     photo.jpg      ->  image
     song.mp3       ->  audio
     report.pdf     ->  PDF (Portable Document Format) document
     script.py      ->  Python code

The extension is a HINT about what kind of data is inside. On Linux the extension is OPTIONAL  --  a file can exist with no extension at all. The system does not enforce it.

2)  What is a FOLDER?

A "folder" is a container that holds files, or other folders, inside it. It has no content of its own  --  it just organizes.

     In Linux and in most technical writing, a folder is also called a DIRECTORY. Same thing, different word. Both terms will show up.

Folders can be nested: a folder inside a folder inside a folder, as deep as you want.

3)  Tree diagram

     Documents/
     |
     |-- notes.txt
     |-- grocery.txt
     |
     `-- School/
          |
          |-- math.pdf
          `-- science.pdf

How to read it:

  -  Documents  is a folder (the trailing  /  is the visual hint).
  -  Inside it: two files ( notes.txt , grocery.txt ) and one sub-folder ( School ).
  -  Inside School: two files ( math.pdf , science.pdf ).

This "tree" shape is how the file system is really organized.

4)  The root  "/"

The topmost folder of the whole system is called the ROOT. Its name IS the single slash character:

     /

Facts:

  -  There is exactly ONE root per Linux system.
  -  Every file and folder lives somewhere inside  / .
  -  The name of the root folder is  /  itself.

Common folders that sit directly inside  / :

     /bin     ->  system programs (ls, cp, mv, ...)
     /etc     ->  system configuration files
     /home    ->  user home folders live here
     /usr     ->  installed programs and libraries
     /var     ->  logs, caches, mail
     /tmp     ->  temporary files (many systems clear this folder on reboot)

Note: the word "root" is also used for the ROOT USER, a special admin account. That is a login, not a folder. In these notes, "root" means the folder  /  unless we clearly say "root user".

5)  The home folder

Inside  /  there is a folder called  home  :

     /home

Each user of the machine gets a personal folder under  /home . If your username is  adarsh , your personal folder is:

     /home/adarsh

Facts:

  -  Your own files (notes, code, downloads, pictures) live under your home folder.
  -  Other users cannot normally read or change what is inside your home folder.
  -  When you open a fresh terminal, it starts you inside your home folder.
  -  Your home folder has a shortcut symbol:  ~  (tilde).

If a machine has multiple users:

     /home/adarsh          ->  Adarsh's home
     /home/priya           ->  Priya's home
     /home/rahul           ->  Rahul's home

6)  A fuller tree

     /                              <- root
     |
     |-- bin/
     |-- etc/
     |-- usr/
     |-- var/
     |-- tmp/
     |
     `-- home/
          |
          |-- adarsh/               <- your home ( ~ )
          |    |-- Documents/
          |    |    |-- notes.txt
          |    |    `-- grocery.txt
          |    |-- Downloads/
          |    `-- Music/
          |
          `-- another_user/
               `-- Documents/

7)  What a path is

A "path" is a piece of text that tells the computer WHERE a file or folder is located in the tree.

The pieces are folder names, separated by  /  . A  /  between two names means "go inside".

Example:

     /home/adarsh/Documents/notes.txt

Read left to right:

     /               ->  start at root
     home            ->  go inside  home
     /               ->  and inside
     adarsh          ->  go inside  adarsh
     /               ->  and inside
     Documents       ->  go inside  Documents
     /               ->  and inside
     notes.txt       ->  the file we want

Every part between two slashes is a folder name, except (possibly) the last part which may be a file name.

Paths come in two kinds, ABSOLUTE and RELATIVE. One character decides which one you are holding.

8)  Absolute path

Rule:  starts with  /

Examples:

     /home/adarsh/notes.txt
     /home/adarsh/Documents/grocery.txt
     /etc/hostname
     /var/log/syslog
     /usr/bin/python3

Properties:

  -  The FULL address from root  /  .
  -  Unambiguous  --  points to exactly one place on the system.
  -  Works from anywhere. It does not matter what your current folder is; the same absolute path always points to the same file.

9)  Relative path

Rule:  does NOT start with  /

A relative path is read starting from your CURRENT WORKING DIRECTORY (CWD)  --  the folder your terminal is currently sitting in.

     Your terminal always sits inside exactly ONE folder at a time, and that folder can be changed while you work. A relative path is read starting from whatever that folder is at the moment the command runs.

Examples of relative paths:

     notes.txt
     Documents/grocery.txt
     Downloads/song.mp3
     School/math.pdf

Properties:

  -  Shorter than absolute.
  -  DEPENDS on the current folder. The same relative path can point to different files if the CWD is different.
  -  Works only if the target actually exists relative to your CWD.

10)  Same file, different paths

Tree:

     /
     `-- home/
          `-- adarsh/
               |-- notes.txt
               `-- Documents/
                    |-- grocery.txt
                    `-- School/
                         `-- math.pdf

The file  math.pdf  has ONE absolute path:

     /home/adarsh/Documents/School/math.pdf

But its relative path changes based on the CWD:

  CWD = /home/adarsh
     relative path:  Documents/School/math.pdf

  CWD = /home/adarsh/Documents
     relative path:  School/math.pdf

  CWD = /home/adarsh/Documents/School
     relative path:  math.pdf

All three relative paths point to the same file. The absolute path stays the same in all three cases.

11)  Name vs path

Do not confuse a NAME with a PATH.

  -  " notes.txt "  used alone in a command is read as a RELATIVE path to a file called  notes.txt  inside your CWD.
  -  " /notes.txt "  is an ABSOLUTE path to a file called  notes.txt  sitting directly in the root folder  /  .

The single leading slash changes the meaning completely.

12)  The four special symbols  ( . , .. , ~ , / )

Four characters have SPECIAL meaning inside a path:  .  ,  ..  ,  ~  and  /  . They are not folder names  --  they are shortcuts that expand to real locations, and the next four sections take one each.

13)  The single dot  " . "

Meaning:  the current folder (your CWD).

Examples  (CWD = /home/adarsh/Documents ):

     .                     ->  /home/adarsh/Documents

     ./notes.txt           ->  /home/adarsh/Documents/notes.txt

     ./School/math.pdf     ->  /home/adarsh/Documents/School/math.pdf

" ./notes.txt "  and just  " notes.txt "  point to the same file when you are in the same CWD. The  ./  in front is OPTIONAL, and both forms are read starting from the folder you are in.

14)  The double dot  " .. "

Meaning:  the parent folder (one level UP from your CWD).

Examples  (CWD = /home/adarsh/Documents ):

     ..                    ->  /home/adarsh

     ../notes.txt          ->  /home/adarsh/notes.txt

     ../Downloads          ->  /home/adarsh/Downloads

Chain  ..  to go multiple levels up.

Examples  (CWD = /home/adarsh/Documents/School ):

     ../..                 ->  /home/adarsh

     ../../notes.txt       ->  /home/adarsh/notes.txt

     ../../..              ->  /home

Read each  ..  as "go up one folder".

15)  The tilde  " ~ "

Meaning:  YOUR home folder ( /home/<username> ).

If your username is  adarsh :

     ~                        ->  /home/adarsh

     ~/notes.txt              ->  /home/adarsh/notes.txt

     ~/Documents              ->  /home/adarsh/Documents

     ~/Documents/grocery.txt  ->  /home/adarsh/Documents/grocery.txt

Facts:

  -  ~  expands to YOUR home folder, based on the logged-in user. Different users get different values.
  -  ~  works from anywhere, whatever your CWD is.
  -  A path starting with  ~  is technically RELATIVE (does not start with  / ), but the shell replaces  ~  with the full absolute path before running the command, so in practice it behaves like an absolute address to your home folder.

16)  The slash  " / "

The slash character has TWO different jobs depending on WHERE it appears.

Job (a):  Leading  /  at the START of a path means "the root folder".

Job (b):  A  /  BETWEEN two names is a separator meaning "go inside".

Example showing both jobs:

     /home/adarsh/notes.txt

     /            ->  Job (a): start at ROOT
     home         ->  a folder name
     /            ->  Job (b): separator
     adarsh       ->  a folder name
     /            ->  Job (b): separator
     notes.txt    ->  a file name

17)  Mixing symbols in one path

The symbols can appear together in the same path.

Examples  (CWD = /home/adarsh/Documents ):

     ./School/math.pdf
        ->  /home/adarsh/Documents/School/math.pdf

     ../Downloads/song.mp3
        ->  /home/adarsh/Downloads/song.mp3

     ~/Music
        ->  /home/adarsh/Music

     ~/Documents/../Downloads
        ->  /home/adarsh/Downloads

Read left to right. Each symbol is expanded in order.

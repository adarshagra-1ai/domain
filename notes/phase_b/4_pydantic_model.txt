B.4  --  Pydantic model to validate input

1)  What Pydantic is

Pydantic is a Python library for defining
DATA MODELS with types and getting
VALIDATION for free.

FastAPI uses Pydantic under the hood. When
you declare a request body as a Pydantic
model, FastAPI:

  -  parses the incoming JSON,
  -  checks that every field matches the
     declared type,
  -  returns 422 automatically if
     validation fails,
  -  gives you a typed Python object
     inside your handler.

Pydantic comes bundled with FastAPI. You
already have it if you installed FastAPI
in B.2.


2)  Defining a model

Import  BaseModel  from  pydantic  and
inherit from it.

Code:

     from pydantic import BaseModel

     class User(BaseModel):
         name: str
         age: int
         is_active: bool = True

Rules:

  -  Each attribute has a TYPE HINT.
  -  A default value ( is_active = True )
     makes that field OPTIONAL.
  -  Without a default, the field is
     REQUIRED.


Using the model directly (not through
FastAPI):

Code:

     user = User(name="adarsh", age=25)
     print(user.name)
     print(user.age)
     print(user.is_active)

Output:
     adarsh
     25
     True


Missing required field:

Code:

     user = User(name="adarsh")

Run:
     ValidationError: 1 validation error for User
     age
       Field required


Wrong type:

Code:

     user = User(name="adarsh", age="not a number")

Run:
     ValidationError: 1 validation error for User
     age
       Input should be a valid integer


3)  Using a model as a request body

Declare it as a parameter with the model
as the type.

Code:

     from fastapi import FastAPI
     from pydantic import BaseModel

     app = FastAPI()

     class User(BaseModel):
         name: str
         age: int
         is_active: bool = True

     @app.post("/users")
     def create_user(user: User):
         return {"created": user.name,
                 "age":     user.age,
                 "active":  user.is_active}

Test with a valid body:

     curl -X POST \
          -H "Content-Type: application/json" \
          -d '{"name":"adarsh","age":25}' \
          http://127.0.0.1:8000/users

Output:

     {"created":"adarsh","age":25,"active":true}


Test with a missing field:

     curl -X POST \
          -H "Content-Type: application/json" \
          -d '{"name":"adarsh"}' \
          http://127.0.0.1:8000/users

Response (status 422):

     {"detail":[{"type":"missing",
                 "loc":["body","age"],
                 "msg":"Field required"}]}

FastAPI returned  422 Unprocessable
Entity  without your handler even running.


4)  Optional fields

Two equivalent styles:

     from typing import Optional

     class User(BaseModel):
         name: str
         nickname: Optional[str] = None

Or the modern union syntax (Python
3.10+):

     class User(BaseModel):
         name: str
         nickname: str | None = None

Both mean:  nickname  is either a string
or  None , and defaults to  None  if
missing.


5)  Nested models

Fields can themselves be Pydantic models.

Code:

     class Address(BaseModel):
         city: str
         zip: str

     class User(BaseModel):
         name: str
         address: Address

Body:

     {"name": "adarsh",
      "address": {"city": "delhi",
                  "zip": "110001"}}

Pydantic validates the nested object too.
A missing  address.city  gives a  422 .


6)  Field constraints  --  Field(...)

For more control (min length, max value,
regex, etc.), import  Field .

Code:

     from pydantic import BaseModel, Field

     class User(BaseModel):
         name: str = Field(min_length=2,
                           max_length=50)
         age:  int = Field(ge=0, le=150)

Common options:

     min_length , max_length      for strings
     ge , le , gt , lt            for numbers
     regex                        regex match
     default                      override default
     description                  docs text


7)  Reading data back  --  model_dump()

Convert a model instance to a plain dict
(for JSON responses or DB inserts).

Code:

     user = User(name="adarsh", age=25)
     print(user.model_dump())

Output:

     {'name': 'adarsh', 'age': 25}

In Pydantic v1 the method was called
.dict() . Modern FastAPI uses Pydantic v2,
where the method is  .model_dump() .


8)  Common errors

  (a)   Forgot to inherit from BaseModel

        Code:

           class User:
               name: str
               age: int

           @app.post("/users")
           def create(user: User):
               ...

        FastAPI does not treat plain
        classes as request bodies. The
        route will not work as expected.
        Inherit from  BaseModel .


  (b)   Type hint but no value or default

        Code:

           class User(BaseModel):
               name: str
               age

        SyntaxError. Every field needs a
        type hint:  age: int .


  (c)   Mixing Pydantic v1 and v2 syntax

        The old style used
        class Config:  inner classes and
        .dict() . Pydantic v2 uses
        model_config = ConfigDict(...)
        and  .model_dump() . If a tutorial
        looks different, check which
        version it targets.


  (d)   Validation runs ONCE at parse time

        After the model instance is
        built, it is a normal Python
        object. Assigning invalid values
        later is NOT rechecked unless you
        opt in with strict validation
        settings.


In B.5 we switch to the database side  --
SQLite basics: create table, insert,
select, update, delete.
